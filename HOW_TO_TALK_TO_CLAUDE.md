# HOW TO TALK TO CLAUDE — Quick Reference
# Print this out or keep it open in a second window

---

## Starting a Session

Just say:
> "Let's work on my games."

Claude will remind you what's going on and ask what you want to do.

---

## To Fix an Existing Game

Say which game and what's wrong:
> "The Squirrel Launcher math problem is too hard"
> "The Dragon game freezes when I die"
> "The Math RPG score isn't saving right"

---

## To Build a Brand New Game

Just say:
> "I want to make a new game."

Claude will ask you questions to figure out what to build BEFORE writing any code.

---

## GOOD ways to describe what you want

✅ "The player should be able to jump over the rocks"
✅ "When the enemy touches the player the player loses a life"
✅ "The game feels too easy — make the enemies move faster after wave 3"
✅ "I want a sound when I collect a coin"
✅ "Can we add this to the main menu page?"

---

## NOT SO GOOD

❌ "Make it better" — better how?
❌ "Add more stuff" — what stuff?
❌ "Fix it" — fix what exactly?
❌ "Start over" — almost never the right answer, ask Claude first
❌ "Make it like Minecraft" — too big, pick ONE thing you like about Minecraft

---

## When Something Looks Broken

Describe EXACTLY what you see:
> "The player falls through the floor"
> "The score goes up but then resets to zero"
> "The page goes white when I click Play"

Don't say: "it's broken" — Claude can't see your screen

---

## Saving Your Work

When Claude says "good place to save":
```
git add .
git commit -m "write what works here"
git push origin main
```
This saves AND puts it live on gus.seaders.org automatically.

---

## If You're Frustrated

Say: "I'm frustrated, can we do something small that works?"
Claude will find a quick win to get momentum back.

---

## The Most Important Rule

**One thing at a time.**
The game gets built piece by piece. Each piece working is a win.
